# CodePlay Insights — SEO, Search & Sharing (Phase 8)

This phase makes CodePlay Insights production-ready for Google Search,
Google News/Discover, and link sharing — without turning it into a
content farm. The priorities are original analysis, clear authorship,
cited sources, speed and mobile UX; the technical SEO below supports
those, it does not substitute for them.

## 1. Per-article metadata

`components/insights/ArticleSEO.tsx` wraps the site-wide
`components/SEO.tsx` and emits, per article:

| Tag | Source |
| --- | --- |
| `<title>` | `article.seo.title` |
| `<meta name="description">` | `article.seo.description` |
| `<link rel="canonical">` | `https://codeplaystudios.com/insights/{slug}` |
| `og:type=article` + `og:title` / `og:description` / `og:image` | article record |
| `og:image:alt` / `og:image:width` / `og:image:height` | featured image record |
| `og:site_name`, `og:locale` | constant |
| `article:published_time` / `article:modified_time` | `publishedAt` / `updatedAt` |
| `article:author` / `article:section` / `article:tag` | editorial author / category / tags |
| `twitter:card=summary_large_image` + title/description/image/alt | article record |

The featured image is the large 16:9 editorial illustration from Phase 5,
so Facebook, LinkedIn, X, Discord and Slack all unfurl with a real image.

`SEO.tsx` gained optional props only — `ogType`, `article`, `ogImageAlt`,
`ogImageWidth`, `ogImageHeight`, `breadcrumbs`. Every existing call site is
unchanged and its defaults are untouched.

## 2. Structured data (JSON-LD)

Emitted where appropriate; **no fabricated fields** (no ratings, no fake
review counts, no invented authors or dates):

- **`NewsArticle`** on every article — `headline`, `description`,
  `datePublished`, `dateModified`, `articleSection`, `keywords`,
  `wordCount` (derived from reading time), `image` as `ImageObject` with
  dimensions, `author` (the editorial entity, typed `Organization`),
  `publisher` (`CodePlay Studios` + logo), `isAccessibleForFree: true`,
  `inLanguage: "en"`, `mainEntityOfPage`.
- **`BreadcrumbList`** — Home › Insights › Category › Article. Provided
  explicitly to `SEO.tsx` so it replaces the generic path-derived trail.
- **`Organization`** + **`WebSite`** — emitted site-wide by `SEO.tsx`
  (unchanged).
- **`Organization` / `Person`** author entity on `/insights/authors/…`.
- **`CollectionPage`** on the Insights hub.

## 3. Authorship & E-E-A-T

CodePlay has not supplied individual journalist bios, so bylines resolve
to a **named, accountable editorial entity** — the *CodePlay Studios
Editorial Team* (`lib/insights/authors.ts`) — rather than invented
people. New trust pages (`lib/insights/editorialPages.ts`, rendered by
`pages/insights/InsightsInfoPage.tsx`):

| Page | Path |
| --- | --- |
| About CodePlay Insights | `/insights/about` |
| Editorial Policy | `/insights/editorial-policy` |
| AI Usage Policy | `/insights/ai-policy` |
| Corrections Policy | `/insights/corrections` |
| Author profile | `/insights/authors/codeplay-studios-editorial-team` |

The AI Usage Policy states plainly that **AI tools assist discovery,
research and drafting, and a human editor reviews and is accountable for
every published article**. It does not claim credentials or hands-on
testing CodePlay has not supplied. Contact details point at the existing
`/contact` route and `info@codeplaystudios.com`.

These pages are linked from every article footer, the Insights hub, and
the site footer.

## 4. Sitemaps

| File | Contents | Maintained by |
| --- | --- | --- |
| `client/public/sitemap.xml` | Marketing pages + the `/insights` hub | Hand-maintained (was stale — now matches real routes) |
| `client/public/sitemap-insights.xml` | `/insights` hub, trust pages, author, **used** category pages, every **published** article with accurate `lastmod` | `npm run insights:seo` |

Both are referenced from `robots.txt`. Drafts, in-review, rejected and
future-scheduled articles are excluded (the query filters
`status = 'published' AND published_at <= now()`). Admin pages and
`/insights/search` are never listed.

## 5. robots.txt

`client/public/robots.txt`:

```
User-agent: *
Allow: /
Disallow: /admin/
Disallow: /insights/search
Sitemap: https://codeplaystudios.com/sitemap.xml
Sitemap: https://codeplaystudios.com/sitemap-insights.xml
```

`/insights` is explicitly **not** blocked.

## 6. RSS

`client/public/insights/rss.xml` (RSS 2.0), regenerated by
`npm run insights:seo`. Each item carries title, canonical link, `guid`,
`pubDate`, category, description (the dek) and — when present — an
`<enclosure>` for the featured image. Unpublished articles are excluded.
Feed is linked from the Insights hub and discoverable at
`/insights/rss.xml`.

## 7. Internal linking

`lib/insights/internalLinks.ts` → `relatedServices(article)` maps an
article's category, entities and tags to the most relevant CodePlay
service page (Flutter → Mobile, Unity → Game Dev, LLM/agent → AI, ERP →
Business Systems, …), always falling back to `/contact`. Rendered as one
understated *“From CodePlay Studios”* block
(`components/insights/RelatedServices.tsx`) — at most two links, not an
ad. The in-article `BusinessCta` (category-aware, single line) is
unchanged.

## 8. The build step

`npm run insights:seo` (`insights-engine/src/publish/run.ts`) runs in CI
**before `vite build`** (`.github/workflows/main.yml`):

1. With `SUPABASE_URL` + `SUPABASE_SERVICE_ROLE_KEY` set — pull published
   articles (service role, read-only) and regenerate
   `client/src/data/insights.generated.ts`, `sitemap-insights.xml` and
   `insights/rss.xml`.
2. Without them — still write valid article-less sitemap + RSS so a
   deploy never ships a stale/missing feed; the snapshot is left alone.
3. Never throws on "no data" / "not configured" / DB error — the step is
   `continue-on-error` and exits 0 so an SEO hiccup can't block a deploy.

Pure builders (`publish/feeds.ts`) are unit-tested (`feeds.test.ts`).

## 9. Google Discover

No manipulation. The ingredients Discover rewards are already in place:
large high-quality 16:9 featured images, strong mobile UX and typography
(Phase 6), non-clickbait headlines (enforced in editorial review),
accurate `datePublished` / `dateModified`, and a clear accountable
publisher.

## 10. Still manual / not done

- **Crawler-perfect static prerendering** of `/insights/*` to HTML.
  Google renders the CSR pages, but Bing and some unfurlers prefer static
  `<head>`. This needs a versioned host rewrite rule (`.htaccess`
  equivalent) that is not in the repo — see architecture doc §14.1.
- Submitting the sitemaps in Search Console (see
  `codeplay-insights-search-console.md`).
- Setting the `VITE_GA4_ID` / `VITE_ADSENSE_*` / `VITE_GSC_VERIFICATION`
  repository variables when those accounts exist.
