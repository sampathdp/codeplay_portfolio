# CodePlay Insights — Editorial Featured Images (Phase 5)

Companion to `docs/codeplay-insights-generation.md`. Phase 5 gives each
article a professional 16:9 featured illustration, generated by Gemini,
optimised, and stored permanently in Supabase Storage. Image generation is
**server-side only**; the API key never reaches the browser. The publish
flow never crashes on an image failure — it uses a category fallback
graphic instead.

---

## 1. Where it runs

`insights-engine/src/generation/imagePipeline.ts`, driven by the same
worker as Phase 4 (`generation/run.ts`, `.github/workflows/insights-generate.yml`).

- **Default: one image per selected article.** After a `full_article`
  job produces a draft that **passes the quality gates** (status
  `review`), the worker generates exactly one featured image. Weak drafts
  (`needs_review` / `rejected`) get no image — no spend on a draft that
  may never publish.
- Admin **Generate / Regenerate Image** actions queue `generate_image` /
  `regenerate_image` jobs, processed in a second loop each run.

```
npm run insights:generate            # includes image for each new review draft
# admin actions queue jobs picked up on the next worker run
```

## 2. Visual identity

`insights-engine/src/generation/imageStyle.ts`:

- **House style** (fixed in code, every prompt): premium tech-publication
  editorial illustration, modern & minimal, one strong focal subject,
  generous negative space, cinematic soft studio lighting, subtle
  futuristic language, restrained cool palette + one warm accent, shallow
  depth of field, thumbnail-safe 16:9, not overcrowded.
- **Per-category direction** (`CATEGORY_VISUALS`) — subject, environment,
  camera for all 16 categories:
  - AI → abstract neural interfaces / model-architecture / AI accelerator hardware, dark studio void
  - Software → code-editor-inspired sculpture (never readable code), bright workspace
  - Gaming → cinematic gaming hardware as a premium product still
  - Game dev → wireframe-to-render, engine-viewport gizmos as forms
  - Cybersecurity → layered shields / network mesh / cryptographic lattice
  - Hardware → GPU / chip die as a jewel-like hero object
  - Cloud → data-center rows / distributed-systems light flow
  - Mobile → sleek device hero, screen shows only abstract light
  - …plus web, developer-tools, startups, saas, big-tech, open-source, emerging-tech, gaming-community
- **Negative requirements** (`NEGATIVE_REQUIREMENTS`, appended to every
  prompt): no text / words / letters / numbers, no logos or brand marks,
  no UI or app screenshots, no fake dashboards, no readable source code,
  no labelled charts, no real people or recognisable faces, no deformed
  hands, no clutter, "not a stock photo", "not a meme", no clichéd glowing
  blue brain.

The pipeline never asks the model to recreate a real publication's
artwork; entities are referenced "without depicting their logos".

## 3. Prompt generator

`generation/imagePrompt.ts` — `buildImagePrompt(input, client?)`:

- Input: article title, category, summary, main entities, the Phase-4
  `imageConcept` seed, aspect ratio.
- Optional cheap Gemini call (fast model, JSON) sharpens **one focal
  subject** and writes plain **alt text**; on any failure it falls back to
  a deterministic template.
- `composePrompt()` assembles the final string with labelled sections:
  **Subject / Environment / Composition / Lighting / Camera / Editorial
  mood / Aspect ratio / Negative requirements**.
- An admin **Edit Prompt** override is used verbatim as the subject line
  (negatives still appended).

## 4. Generation → optimise → store

`generateFeaturedImage(deps, input)`:

1. Build the prompt (§3).
2. **Gemini image call** — `insights-engine/src/gemini/image.ts`.
   `RealGeminiImageClient` handles both SDK surfaces:
   - `imagen-*` → `models.generateImages` (`aspectRatio: "16:9"`, `negativePrompt`)
   - `gemini-*-image` → `models.generateContent` with an `IMAGE` response
     modality; aspect ratio steered via the prompt.
   Default model `GEMINI_IMAGE_MODEL` = `gemini-3.1-flash-image`.
3. **Optimise** — `storage/processor.ts` `SharpImageProcessor` (sharp,
   optional dependency, lazy-loaded; passthrough fallback if unavailable):
   `fit: cover, position: attention` crop to each 16:9 size, WebP q82.
   Default variants: `primary` 1600×900, `og` 1200×630, `w1200` 1200×675,
   `w800` 800×450, `w400` 400×225.
4. **Store** — `storage/images.ts` `SupabaseImageStore`. Every variant is
   **downloaded and uploaded** to bucket `insights-media` (never
   hotlinked):
   ```
   insights/YYYY/MM/<article-slug>/primary.webp
                                   og.webp  w1200.webp  w800.webp  w400.webp
   ```
   Bucket is public (long-lived cache headers) so the static site loads
   images without signed URLs.
5. Emit an `insights_ai_usage` row for the image call (flat cost per model
   from `ai_budget.imagePricingUsd`, default $0.04).

`persistImage.ts` writes the result to `insights_articles`
(`featured_image_url`, `featured_image_alt`, `featured_image_status`,
`image_is_ai_generated`, `image_prompt`, `featured_image_model`,
`featured_image_generated_at`, `featured_image_width/height/bytes`,
`featured_image_storage_path`, `featured_image_variants` jsonb) and one
`insights_image_assets` row per variant — **only when
`featured_image_is_manual = false`**.

---

## 5. Metadata stored

Per article: image URL, prompt, generation model, `generated_at`,
AI-generated flag, alt text, width, height, file size, storage path, and
the responsive-variant list. Per variant (`insights_image_assets`): label,
url, storage_path, content_type, width, height, bytes, `is_primary`,
`source` (`generated`/`stock`/`manual`/`fallback`), model, prompt, alt_text.

---

## 6. Alt text

Generated alongside the prompt — a plain one-line description of the
illustration, capped at 180 chars, trailing punctuation stripped, **no
keyword stuffing**. Fallback graphics get
`"CodePlay Insights <category> category illustration"`.

---

## 7. Transparency

`insights_articles.image_is_ai_generated` is `true` for generated
illustrations. `ArticleImage.aiGenerated` carries it to the client, and
`InsightsArticle.tsx` renders the caption **"AI-generated editorial
illustration"** under the hero image. Manual and fallback images are not
labelled that way.

---

## 8. Regeneration & manual images

`client/src/lib/insights/admin/images.ts`:

| Action | Effect |
|---|---|
| **Generate Image** | `generateImage(articleId)` → queues `generate_image` |
| **Regenerate Image** | `regenerateImage(articleId, promptOverride?)` → queues `regenerate_image` |
| **Edit Prompt** | `editImagePrompt(articleId, prompt)` → RPC updates `image_prompt` only, no regeneration |
| **Upload Manual Image** | `uploadManualImage()` uploads the file to Storage with the admin's session, then `insights_set_manual_image` records it and sets `featured_image_is_manual = true` |
| **Remove Image** | `removeImage(articleId)` → RPC clears all image columns + asset rows |

**A manual image is never automatically replaced.** Enforced twice:
`insights_request_image` refuses to queue a job while a manual image is
set ("remove it first"), and `generateFeaturedImage` returns
`skipped_manual` unless `force` is set. `persistImage` and every
image-column write is scoped `.eq("featured_image_is_manual", false)`.

## 9. Fallback (publish never crashes)

If the Gemini image call fails (RAI filter, timeout, quota — note the
**free tier cannot generate images at all**) **or** processing/storage of
the generated image fails, `generateFeaturedImage` falls back in two
tiers:

1. **Stock photo** (`generation/stockImage.ts`). When `PEXELS_API_KEY` is
   set, search Pexels for a landscape editorial photo keyed to the
   article's category, run it through the same sharp pipeline (identical
   16:9 WebP variants), and store it. Returns `status: "stock"`,
   `image_is_ai_generated = false`, and a `featured_image_credit` JSON blob
   (`{ provider, photographer, photographerUrl, sourceUrl }`).
   `InsightsArticle.tsx` renders a **"Photo: <name> on Pexels"** caption.

2. **Deterministic category SVG** (`generation/imageFallback.ts` — a
   restrained gradient + category-tinted geometric motif, no text,
   1600×900), stored as `fallback.svg`. Returns `status: "fallback"`,
   `image_is_ai_generated = false`.

The article stays in `review` with a usable image. Only if the SVG upload
*also* fails does it return `status: "failed"` (article marked
`featured_image_status = "failed"`, no crash) — an admin can retry.

## 10. Cost control

- One generated image per selected article; regeneration only on explicit
  admin request.
- 2–3 articles/day ⇒ normally 2–3 generated images/day.
- Each image call is logged in `insights_ai_usage` (model, request_count,
  `estimated_cost_usd`, status `ok`/`error`). Failures are recorded with
  `status = "error"`, cost 0.
- `ai_budget` gains `imagePricingUsd` (per-model flat cost). The worker's
  daily USD / call totals include image calls, so the existing
  `dailyUsdCap` / `dailyCallCap` guards apply to images too.

## 12. Environment

Server / CI only:

```
GEMINI_API_KEY=            # required (shared with Phase 4)
GEMINI_IMAGE_MODEL=        # optional — default gemini-3.1-flash-image (needs billing)
PEXELS_API_KEY=            # optional — stock-photo fallback when generation fails
INSIGHTS_MEDIA_BUCKET=     # optional — default insights-media
SUPABASE_URL=
SUPABASE_SERVICE_ROLE_KEY=
```

No new GitHub secret beyond the Phase 4 set. Create the Storage bucket via
`supabase db push` (the migration does it) or the dashboard.
